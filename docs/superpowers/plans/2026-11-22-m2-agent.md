# void.ai Milestone 2 (Agent, Sandbox, Review) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** void.ai becomes an agent. It calls tools (read, list, glob, grep, edit, write, bash) in a loop. Every change lands in a per-chat overlay that the user reviews in a dockable panel. `bash` runs in a bubblewrap + Landlock sandbox where everything outside the workspace overlay is read-only or hidden.

**Architecture:** The new void-core modules are `overlay`, `tools`, `sandbox`, `permissions` and `agent`. A new tiny binary crate, `crates/void-sandbox`, provides the Landlock helper (`void-sandbox-exec`). The engine reuses milestone 1's stream task:
1. When a reply ends with tool calls, the main loop spawns a tool-runner task.
2. The tool results come back as messages to the main loop.
3. The main loop then starts the next stream round.

The GUI adds tool and approval cards, an agent picker, the Review tab and status pills.

**Tech Stack:** milestone 1's stack, plus:
- `similar` 3 (diffs)
- `ignore` 0.4 (.gitignore)
- `globset` 0.4
- `regex`
- `tokio-util` 0.7 (`CancellationToken`)
- `landlock` 0.4.8 (helper only)
- the system `bwrap` 0.13

**Spec:** `docs/superpowers/specs/2026-11-22-m2-agent-design.md` (and `2026-11-22-void-ai-design.md`)

## Global Constraints

- void-core stays UI-agnostic. The Landlock code lives only in `crates/void-sandbox`.
- **Never run agent commands unsandboxed.** If `bwrap` is missing or fails its start-up check, `bash` returns an error saying why.
- **All agent writes go to the chat's overlay.** Nothing writes into the real workspace except an accept action the user takes.
- **File tools refuse paths outside the workspace**, including through symlinks, and refuse paths under the hidden list.
- **Overlay root:** `~/.local/share/void.ai/workspaces/<ws>/overlays/<conversation-id>/{upper,work,base,checkpoint,meta.json}`.
  - Sandbox target: `…/workspaces/<ws>/sandbox-target/`.
  - Cache layers: `~/.local/share/void.ai/cache-overlay/<name>/{upper,work}`.
- **Hidden list (defaults, skipped when the path doesn't exist):**
  - `~/.ssh ~/.gnupg ~/.aws ~/.netrc ~/.config/gh ~/.local/share/keyrings`
  - `~/.mozilla ~/.config/chromium ~/.config/google-chrome`
  - `~/.config/opencode ~/.config/void.ai ~/.local/share/void.ai ~/.claude ~/.config/Claude`
  - `/run/user/$UID /run/dbus /var/run/docker.sock /run/docker.sock /run/podman`
- **Cache defaults** (when present): `~/.cargo/registry ~/.cargo/git ~/.npm ~/.cache/pip ~/.cache/uv ~/.proto/tools ~/.rustup/toolchains`.
- **Sandbox environment** is only `PATH HOME USER LANG TERM=dumb CARGO_HOME RUSTUP_HOME PROTO_HOME` (each if set), plus `CARGO_TARGET_DIR`.
- **bash defaults:** 120 s timeout (600 s max). Model output is capped at the last 30,000 bytes plus `…(N bytes cut)`.
- **Agent loop:** a step limit of 50 tool rounds.
- **File tools:** `read` returns at most 2,000 lines. `AGENTS.md`/`CLAUDE.md` are capped at 32 KB.
- **Compaction buffer** = `min(123048, context_limit / 2)`.
- **Default permissions:**
  - `read list glob grep edit write` → allow; `bash` → ask.
  - The plan agent denies `edit write bash`.
- Commit after each task (`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). `moon run :format :lint :test :build` must pass at every commit.
- **Never test the sandbox by pointing a model at destructive commands.** Sandbox safety is proven by integration tests that run the sandbox directly against canary files in temporary directories.

## Review Focus

1. **Escape attempts from bash:**
   - writing `$HOME`;
   - deleting a file outside the workspace;
   - reaching the session bus (`systemd-run --user`) or `/run/user/$UID`;
   - reading `~/.ssh`;
   - writing `.git`.

   All must fail, and canaries must survive. → `sandbox_blocks_*` tests (Task 4).
2. **Symlink escape through the file tools.** A symlink in the overlay or workspace pointing at `~/.ssh/...` or `/etc/passwd`: `read`, `grep` and `edit` refuse it. → `confine_refuses_symlink_escape` (Task 3).
3. **Accept while the real file changed** (the user edited it in another editor): a conflict, never a silent overwrite. → `accept_detects_conflict` (Task 2).
4. **Stop during a running bash command:** the process group dies within 1 s, the partial output is kept, and nothing is left running. → `bash_stop_kills_process_group` (Task 5).
5. **Deleting a chat with pending changes:** the overlay directory is removed with it, and nothing reaches the workspace. → `delete_conversation_discards_overlay` (Task 7).

### Task 2: Overlay

**Files:** create `crates/void-core/src/overlay.rs`. Add deps `similar`, `ignore`.

**Interfaces:**
- **Produces:**
  - `pub struct Overlay`, which is Clone and cheap: two `Arc<PathBuf>`s.
  - `Overlay::open(dir: &Path, workspace: &Path) -> io::Result<Overlay>`: creates `upper/ work/ base/`.
  - `upper()`, `work()`, `workspace()`, `dir()`.
  - `pub enum Entry { Missing, File(PathBuf), Dir(PathBuf) }`, where the path is the one to read.
  - `resolve(&self, rel: &Path) -> Entry`, following the overlay rules:
    - a whiteout (char device 0:0) in upper at `rel` or at any ancestor means `Missing`;
    - an upper file or directory wins;
    - an opaque upper ancestor (xattr `user.overlay.opaque == "y"`) hides lower;
    - otherwise lower.
  - `read(&self, rel) -> io::Result<Vec<u8>>`.
  - `read_dir(&self, rel) -> io::Result<Vec<DirItem>>`, merged and sorted, where `DirItem { name: String, is_dir: bool }`.
  - `write(&self, rel, bytes: &[u8]) -> io::Result<()>`:
    - creates upper parents;
    - first records base: copies the lower file to `base/rel` if lower has it and base doesn't yet, or writes a `base/rel.void-absent` marker when lower lacks it;
    - then writes upper atomically.
  - `snapshot_bases(&self) -> io::Result<()>`: for each upper regular file or whiteout without a base record, copies lower (or writes the absent marker). Skips `ignore`d paths.
  - `pub enum ChangeKind { Added, Modified, Deleted, ReplacedDir }`.
  - `pub struct Change { pub path: PathBuf /*relative*/, pub kind: ChangeKind, pub ignored: bool, pub conflict: bool }`.
  - `changes(&self) -> Vec<Change>`:
    - walks upper; `.gitignore` comes from the merged view via `ignore::gitignore`;
    - ignored paths appear only if they have a base record (i.e. were written by file tools);
    - `conflict` means the base exists and the current lower ≠ base.
  - `pub struct Hunk { pub index: usize, pub old_start: usize, pub old_len: usize, pub new_start: usize, pub new_len: usize, pub lines: Vec<(char /*' ' '-' '+'*/, String)> }`.
  - `diff(&self, rel) -> io::Result<Vec<Hunk>>`: base (or empty) vs upper, with `similar` and 3 lines of context.
  - `accept_file(&self, rel, force: bool) -> Result<(), OverlayError>`.
  - `reject_file(&self, rel) -> io::Result<()>`.
  - `accept_hunk(&self, rel, index, force) -> Result<(), OverlayError>`.
  - `reject_hunk(&self, rel, index) -> io::Result<()>`.
  - `accept_all(&self, keep_ignored: bool) -> Result<Vec<PathBuf> /*conflicts skipped*/, OverlayError>`.
  - `reject_all(&self)`.
  - `discard(self) -> io::Result<()>`: removes `dir`.
  - `checkpoint(&self) -> io::Result<()>`: replaces `checkpoint/` with copies of `upper/` and `base/`, using `cp -a --reflink=auto` via std::process.
  - `restore_checkpoint(&self) -> io::Result<bool>`.
  - `take_rejections(&self) -> Vec<String>`: reads and clears `meta.json` `rejected: [..]`.
  - `pub enum OverlayError { Conflict(PathBuf), Outside(PathBuf), Io(io::Error) }`.
- **Accept rules (from the spec):**
  - **Conflict:** base exists and lower ≠ base, and not `force` → `Conflict`.
  - **Added/Modified:** atomic write to lower, keeping lower's mode (or upper's for new files), then remove the upper and base entries.
  - **Deleted:** confirm the canonical lower path starts with the canonical workspace, then remove it (recursively for a directory), then remove the whiteout and base.
  - **ReplacedDir:** delete lower children that aren't in upper, then accept the children.
  - **Hunk accept:** lower = base with that hunk applied, base = lower; drop upper when it equals lower.
  - **Hunk reject:** upper = upper with that hunk reverted; drop upper and base when upper equals base. Record "rejected <path> hunk <i>: -<n> +<m> lines" in meta.
- **Test helper:** `#[cfg(test)] fn bwrap_exec(overlay, script)` runs `bwrap --ro-bind / / --dev /dev --proc /proc --tmpfs /tmp --overlay-src <ws> --overlay <upper> <work> <ws> --chdir <ws> bash -c <script>`. It creates real whiteouts and opaque directories. Tests that need it return early with a printed note when `/usr/bin/bwrap` is missing.

### Task 4: Sandbox and the Landlock helper

**Files:** create `crates/void-core/src/sandbox.rs`, and `crates/void-sandbox/{Cargo.toml,moon.yml,src/main.rs}` (bin `void-sandbox-exec`, dep `landlock = "0.4.8"`). Add it to the workspace members.

**Interfaces:**
- **Produces:**
  - `pub struct SandboxSettings { pub hidden: Vec<PathBuf>, pub expose: Vec<PathBuf>, pub caches: Vec<PathBuf>, pub network: bool, pub timeout: Duration }`, with `Default` per Global Constraints. It's `Serialize`/`Deserialize` in config under `[sandbox]`, with paths stored with a `~` prefix and expanded at load.
  - `pub enum Availability { Ready { landlock: bool }, Unavailable(String) }`.
  - `pub struct Sandbox { bwrap: PathBuf, helper: Option<PathBuf>, data_dir: PathBuf, settings: SandboxSettings, lock: Arc<tokio::sync::Mutex<()>> }`.
  - `Sandbox::new(data_dir, settings) -> Sandbox`. It finds `bwrap` on PATH and the helper via env `VOID_AI_SANDBOX_EXEC`, then the sibling of `current_exe()`, then that directory's parent (for `target/debug/deps`).
  - `availability(&self) -> Availability`:
    - runs `bwrap --ro-bind / / --unshare-user true`, with a 5 s timeout;
    - `landlock` = the helper exists and `void-sandbox-exec --probe` exits 0.
  - `pub struct RunPlan { pub workspace: PathBuf, pub upper: PathBuf, pub work: PathBuf, pub target_dir: PathBuf, pub command: String }`.
  - `bwrap_args(&self, plan: &RunPlan) -> Vec<OsString>`. A pure function, in this order:
    1. `--die-with-parent --new-session --unshare-pid --unshare-ipc --unshare-uts [--unshare-net if !network]`
    2. `--ro-bind / / --dev /dev --proc /proc --tmpfs /tmp`
    3. `--tmpfs <h>` for each hidden path that exists and isn't in `expose`
    4. for each existing cache `c`: `--overlay-src c --overlay <data>/cache-overlay/<name>/upper <…>/work c`
    5. `--overlay-src ws --overlay upper work ws`
    6. `--ro-bind ws/.git ws/.git` if `.git` exists
    7. `--bind target_dir target_dir` (`mkdir -p` first)
    8. `--clearenv` and `--setenv` for each allowed variable, plus `--setenv CARGO_TARGET_DIR target_dir`
    9. `--chdir ws --`, then the helper with `--write ws --write /tmp --write target_dir [--write each cache] -- bash -lc <command>`, or `bash -lc <command>` when there's no helper.

    `<name>` = `sha256(path)[..12]`.
  - `pub struct ExecResult { pub exit: Option<i32>, pub output: String /*capped*/, pub timed_out: bool, pub cancelled: bool, pub cut_bytes: usize }`.
  - `run(&self, plan: RunPlan, cancel: CancellationToken, stream: Option<UnboundedSender<String>>) -> ExecResult`:
    - takes `lock` when the cache list isn't empty;
    - spawns bwrap with `process_group(0)` and stdout and stderr piped and merged in read order;
    - streams chunks;
    - on timeout or cancel, `kill(-pgid, SIGKILL)` and waits;
    - caps the output.
- **The helper (`crates/void-sandbox/src/main.rs`):**
  - **Args:** `--probe`, or `--write <dir>... -- <argv>`.
  - **Ruleset:**
    - `Ruleset::default().handle_access(AccessFs::from_all(ABI::V5))?.scope(Scope::AbstractUnixSocket | Scope::Signal)?.create()?`;
    - `add_rules` with read access to `/`;
    - full access to each `--write` dir;
    - `restrict_self()`.
    - **Then** `execvp`.
  - **Best effort:** use `set_compatibility(CompatLevel::BestEffort)`, and print `void-sandbox: landlock partial` to stderr when the status isn't fully enforced.
  - `--probe`: applies a ruleset in a forked child and exits 0 if it was enforced.

### Task 6: Permissions, agent profiles, system prompt

**Files:** create `crates/void-core/src/{permissions.rs,agent.rs}`; modify `config.rs` (agents and sandbox sections).

### Task 7: The agent loop in the engine

**Files:** modify `crates/void-core/src/{engine.rs,context.rs}`.

**Interfaces:**
- **Consumes:** everything above.
- **Produces:**
  - **New commands:**
    - `SetConversationAgent(ConversationId, Option<String>)`
    - `Approve { id: u64, decision: Decision }`
    - `ListChanges(ConversationId)`
    - `Diff { conversation, path: PathBuf }`
    - `AcceptFile { conversation, path, force: bool }`, `RejectFile { conversation, path }`
    - `AcceptHunk { conversation, path, index, force }`, `RejectHunk { conversation, path, index }`
    - `AcceptAll { conversation, keep_ignored: bool }`, `RejectAll(ConversationId)`
    - `Compact(ConversationId)`
    - `ClearSandboxCaches`
  - **New events:**
    - `SandboxStatus(Availability)`, emitted at start.
    - `ToolStarted { conversation, call_id, name, summary }`
    - `ToolOutput { conversation, call_id, text }`
    - `ToolFinished { conversation, call_id, output: ToolOutput }`
    - `ApprovalNeeded(ApprovalRequest)`
    - `ApprovalResolved { id }`
    - `Changes { conversation, changes: Vec<Change> }`, emitted after every tool round and every review command.
    - `Diff { conversation, path, hunks: Vec<Hunk> }`
    - `ReviewError { conversation, path, error: String }` (including conflicts)
    - `Compacted(ConversationId)`
  - **Flow:**
    1. **Start of a user turn** (send or retry), only when the workspace has a root and the agent has tools: open the overlay, call `checkpoint()`, and set `round = 0`.
    2. **Building the request** uses `agent::system_prompt` and `registry.specs(agent.tools minus deny)`, with no tools in Scratch.
    3. **When a round finishes with ToolCall parts:** if `round == 50`, finish with a note "step limit reached". Otherwise spawn the **tool runner task** for those calls, in order. For each call:
       - parse the args;
       - `Action` = the agent's deny list takes precedence, otherwise `Permissions::decide`;
       - on Ask, use the engine's approver, which emits `ApprovalNeeded` and waits on a oneshot that `Approve` fulfils;
       - on Allow, `run`, streaming `ToolOutput`;
       - on Deny, output "denied by the user".
    4. Each result goes to the main loop, which appends a `Role::Tool` message (`ToolResult`) and emits `ToolFinished`. Rejection notes from `take_rejections()` are appended to the first result of the next round.
    5. **When all results are in:** save, emit `Changes`, `round += 1`, start the next stream round.
  - **Stop:** cancels the token and aborts the tasks. Pending approvals resolve to Deny. The partial message is kept as today, and the overlay is kept.
  - **Retry:** before popping messages, `restore_checkpoint()` on that conversation's overlay. Also pop trailing `Role::Tool` and assistant messages back to the last user message.
  - **Delete conversation:** also `Overlay::discard`.
  - `AlwaysForWorkspace(prefix)` appends `Rule { tool, prefix, action: Allow }` and saves the permissions.
  - **Compaction:**
    - before each stream round, `context::needs_compaction(conv, profile)` is checked: the context estimate, counting from the last Summary marker, exceeds `context_limit − buffer`;
    - if so, run a no-tools request "Summarise the conversation so far for yourself: goals, decisions, files touched, current state, open threads." and append `Message{role: Assistant, parts: [Part::Summary(text)]}`;
    - `build_request` then sends the system prompt plus `"Summary of earlier conversation:\n…"` as the first user message, plus the messages after the marker.
